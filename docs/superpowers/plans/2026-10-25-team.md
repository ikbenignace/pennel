# Fase E — Cloud Team — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An owner creates a team in the app, pays per seat through Stripe, invites colleagues by e-mail, and shares read-only templates and a team dictionary. Members accept in their app, get Team limits and EU-only processing, and keep their meetings private. Removing a member returns them to their own account with nothing lost.

**Architecture:** The server adds workspaces, members, invites and a small team configuration (templates + dictionary, versioned for ETag/304) to Postgres, and extends the fase C billing code with `workspace_id` and quantity. `entitlements()` returns Team limits and `eu_only` for members of a workspace with an active Team subscription; `proxy::admit` refuses a non-EU upstream for them. The core caches the team configuration in `<data_dir>/team.json`; `TemplateStore` lists team templates next to built-in and own ones; the engine merges the team dictionary into the effective settings at the four dictionary sites. The desktop sync runner refreshes the team configuration on every tick.

**Tech Stack:** Server: Rust 2024, axum 0.8, sqlx 0.8, the fase C `StripeApi`, `Mailer`. Core: Rust, ureq 3, uniffi 0.32, mockito, tempfile. Desktop: Tauri 2, TypeScript, node test runner. Native: SwiftUI (disabled parity only).

## Global Constraints

- No team route ever returns or touches another account's vault, objects, usage details or devices. Admins see member e-mail, role and joined date only.
- Never log team names, template names or bodies, dictionary terms, or e-mail addresses. Logs keep route template, status, duration and account id.
- Team templates and the team dictionary are server-readable (spec decision 2). They are stored as given and never executed; in the app they are prompt data exactly like own templates.
- One workspace per account (`unique(user_id)` on members). Roles: `owner` (exactly one), `admin`, `member`. Only the owner changes roles or transfers ownership. Owners and admins invite, remove, and edit templates and the dictionary.
- Seats: the Stripe quantity equals the member count, owner included; a minimum of 2 at checkout. An accepted invite raises the quantity with `proration_behavior=create_prorations`, and a removal lowers it with `proration_behavior=none`.
- Limits: a member of a workspace with an active Team subscription gets `limits_for(Plan::Team)` and `eu_only = true`, regardless of a personal subscription.
- Sizes: template body ≤ 32_768 bytes, name 1–60 chars, slug `^[a-z0-9-]{1,60}$`; dictionary ≤ 1_000 terms, each 1–100 chars; invites expire after 14 days.
- Dutch user-facing strings exactly as written here and in spec §5.
- Server: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`. musli: `cd core && cargo fmt -- --check && cargo clippy --lib --tests -- -D warnings && cargo test`, `make core && make test && make app`, `cd apps/desktop && npm ci && npm run build && npm test`, `cd apps/desktop/src-tauri && cargo test`.

## Review Focus

1. An admin calls every team route with a member's user id → none returns that member's objects, devices or usage. Test in Task 2 (a sweep over all routes asserting the response JSON has no `object`, `device` or `usage` keys for other users).
2. A member is removed while a sync pass runs on their device → their vault and objects are untouched; the next `GET /v1/account` shows plan `free` (or their own plan); team templates disappear from the app, and a meeting summarised with a removed team template falls back to the default. Tests in Task 2 (server) and Task 7 (core).
3. Two invites accepted at the same moment for the last seats → the Stripe quantity ends equal to the member count (serialise on the workspace row; re-read the count before calling Stripe). Test in Task 3.
4. The team dictionary plus a long own dictionary → own terms come first; the merged list respects `MAX_PROMPT_CHARS` (`capped_terms`) and dedups case-insensitively. Test in Task 8.
5. An `eu_only` member when `PENNEL_LLM_REGION=us` → 503 `eu_only` before any upstream call; a non-team account is served. Test in Task 4.
6. The owner tries to delete their account with other members → 409 `workspace_owner`, nothing deleted. Test in Task 2.

    - `DELETE /v1/workspace/invites/{id}`.
    - `GET /v1/invites`: pending, unexpired invites for the caller's e-mail: `[{id, team_name, inviter_email}]`.
    - `POST /v1/invites/{id}/accept`: the caller's e-mail must match, they must not be in a workspace, and the invite must be unexpired. Inserts the member and bumps the seats (Task 3).
    - `POST /v1/invites/{id}/decline`.
    - `DELETE /v1/workspace/members/{user_id}`: admin. The owner cannot be removed (`409 owner`).
    - `PATCH /v1/workspace/members/{user_id} {role: "admin"|"member"}`: owner only.
    - `POST /v1/workspace/transfer {user_id}`: owner only; the target must be a member.
    - `POST /v1/workspace/leave`: not the owner (`409 owner`).
    - `DELETE /v1/workspace`: owner only, no other members and no active subscription (`409 workspace_active`).
